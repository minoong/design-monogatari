## 사용법

```tsx
import { SwitchField } from '@/components/ui/switch-field';

export function Example() {
  return (
    <SwitchField
      label="선루프 열어 보기"
      status={{ on: '열림', off: '닫힘' }}
      onChange={(event) => console.log(event.target.checked)}
    />
  );
}
```

[`Switch`](/docs/components/switch)와 이름표를 매번 `Label`로 이어 주는 대신 한 `label`로 묶었습니다. 스위치와 글자 사이 간격까지 눌리고, 높이는 32px라서 옆의 작은 버튼과 맞습니다. 이름표는 `label`로 주고, 나머지 속성(`checked`, `defaultChecked`, `onChange`, `name`, `disabled` 등)은 스위치로 갑니다. `className`은 바깥 `label`에 붙습니다.

이름은 상태와 상관없이 고정입니다. 상태에 따라 이름표 글자가 바뀌면 낭독기가 "선루프 닫아 보기, 켜짐"처럼 이름과 상태를 어긋나게 읽고, 음성 제어에서도 이름이 어긋납니다. 상태를 글자로도 보이고 싶으면 `status`를 쓰십시오.

## 예시

`status`는 선택입니다. 없으면 스위치와 이름표만 놓입니다.

## 접근성

- 스위치의 접근성 이름은 이름표입니다. 스위치가 `label` 안에 들어 있어서 따로 `htmlFor`를 이을 필요가 없고, 이름표 글자를 눌러도 스위치가 켜지고 꺼집니다.
- 상태 글자(`status`)는 스위치가 이미 알리는 켜짐/꺼짐과 같은 정보라서 `aria-hidden`입니다. 낭독기가 같은 말을 두 번 읽지 않습니다.
- 상태 글자가 바뀌는 폭만큼 자리를 미리 잡아서(긴 쪽의 글자를 보이지 않게 깔아 둡니다) 글자가 바뀌어도 줄의 폭이 변하지 않습니다.
- `label`에는 글자나 아이콘만 넣으십시오. 링크나 버튼을 넣으면 `label` 안에 누를 수 있는 요소가 겹칩니다. 다른 `label`이나 `Field`의 라벨 안에 넣어도 `label`이 중첩됩니다. 도움말이나 오류 문구는 `Field`와 함께 쓰고 `aria-describedby`를 이으십시오.
- `form.reset()`으로 폼을 되돌리면 스위치와 함께 상태 글자도 처음 값으로 돌아갑니다. 리셋 직후 첫 클릭에서는 React가 `onChange`를 호출하지 않을 수 있으니(React가 리셋을 알지 못합니다), 폼 값은 `onChange`가 아니라 제출 때 읽으십시오. 코드에서 `input.checked`를 직접 바꾸는 것은 브라우저가 알리지 않으므로 상태 글자가 따라가지 못합니다(`checked`를 넘기는 제어 방식을 쓰십시오).
- 스위치의 접근성 항목은 [`Switch`](/docs/components/switch)를 따릅니다. 비활성이면 `cursor-not-allowed`와 옅은 글자색으로 보이고, 스위치 자체의 비활성 색이 상태를 알립니다.
- 감소 모션이면 상태 글자는 굴러서 바뀌지 않고 투명도만 바뀝니다.
