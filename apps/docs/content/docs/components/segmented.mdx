## 사용법

```tsx
import { Segmented, SegmentedItem } from '@/components/ui/segmented';

export function TaxChoice() {
  return (
    <Segmented
      aria-label="과세 구분"
      defaultValue="taxed"
      onValueChange={(value) => console.log(value)}
    >
      <SegmentedItem value="taxed">과세</SegmentedItem>
      <SegmentedItem value="exempt">면세</SegmentedItem>
    </Segmented>
  );
}
```

짧은 이름의 선택지 둘에서 넷 중 하나를 고를 때 씁니다. 항목마다 설명이나 가격이 붙는 선택은 [`OptionRow`](/docs/components/option-row)를, 선택지가 많거나 긴 목록은 [`NativeSelect`](/docs/components/native-select)를 쓰십시오. 속은 네이티브 라디오라서 `name`을 주면 폼으로 그대로 전송됩니다.

`value`와 `onValueChange`로 제어하거나, `defaultValue`로 비제어로 쓸 수 있습니다.

## 예시

### 선택 표시의 모양

`indicator`로 모양을 고릅니다. 어느 모양이든 선택이 바뀌면 이전 항목에서 새 항목으로 미끄러지고, 감소 모션이면 미끄러지지 않고 바로 옮겨 갑니다.

## 접근성

- 묶음은 `role="radiogroup"`이고 항목은 네이티브 `input[type=radio]`입니다. 그래서 스크린 리더가 라디오 버튼 묶음으로 읽고, 같은 `name`끼리 방향키 이동과 Tab 진입을 브라우저가 처리합니다. 선택된 항목이 있으면 Tab은 그 항목으로 들어가고, 선택이 없으면 첫 항목으로 들어갑니다. 묶음에는 `aria-label`이나 `aria-labelledby`로 이름을 꼭 주십시오(둘 중 하나가 없으면 타입 오류입니다). 사파리는 기본 설정에서 Tab으로 라디오에 닿지 않고 Option+Tab을 써야 합니다. 모든 네이티브 컨트롤이 같습니다.
- 선택은 색뿐 아니라 선택 표시의 모양(테두리가 있는 알약, 아래 막대, 테두리 링)으로도 구분되고, 선택된 항목의 글자색이 진해집니다. 알약의 윤곽은 연한 헤어라인(`border-border`)이라 트랙과의 대비는 라이트 약 1.4:1, 다크 약 1.6:1로 3:1에 못 미칩니다. 선택된 항목의 글자색(4.66:1에서 16.83:1)이 함께 알리고, 더 또렷해야 하면 `underline`이나 `ring`을 쓰십시오. 글자 굵기는 바뀌지 않아서 선택해도 폭이 변하지 않습니다.
- 윈도 고대비 같은 강제 색상 모드에서는 배경색이 지워지므로 막대는 `Highlight` 배경, 알약과 링은 `Highlight` 테두리로 남습니다. 포커스 링은 실제 아웃라인이라 그대로 보입니다.
- 키보드 포커스는 항목 둘레의 2px 아웃라인으로 보입니다(간격은 2px이고, 트랙 패딩이 4px인 알약만 간격 없이 알약 테두리에 붙습니다). 항목 높이는 알약과 링이 36px, 밑줄이 44px이고 알약 묶음은 패딩을 더해 44px입니다.
- 선택 표시는 넘치지 않는 스프링(`SPRING.settle`)으로 미끄러지고, `prefers-reduced-motion`이면 바로 옮겨 갑니다.
- 비활성 항목은 흐려지고 호버해도 진해지지 않으며, 클릭과 방향키 이동에서 건너뜁니다. 왜 고를 수 없는지는 근처에 설명 글을 두고 `aria-describedby`로 묶으십시오.
- 항목에는 보이는 글자가 있어야 합니다. 아이콘만 있는 항목은 라디오에 이름이 없으므로 지원하지 않습니다.
