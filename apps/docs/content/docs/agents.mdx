이 문서는 사람이 보는 HTML과 별개로 에이전트가 읽기 좋은 Markdown을 같은 주소 체계로 내어 줍니다. 모두 문서 내용에서 자동으로 만들어지므로 따로 관리하는 파일이 없습니다.

| 경로                               | 돌려주는 것                          | 언제 쓰는가                  |
| ---------------------------------- | ------------------------------------ | ---------------------------- |
| [`/llms.txt`](/llms.txt)           | 모든 페이지의 제목, 주소, 한 줄 설명 | 어떤 페이지가 있는지 찾을 때 |
| [`/llms-full.txt`](/llms-full.txt) | 모든 페이지 본문을 이어 붙인 것      | 문서 전체를 한 번에 줄 때    |
| `/docs/<경로>.md`                  | 그 페이지 하나의 Markdown 본문       | 필요한 페이지만 읽을 때      |
| `Accept: text/markdown`            | 같은 주소의 Markdown (HTML 대신)     | 주소를 바꾸기 어려운 도구    |

## 에이전트용 문서

### `docsLlms`

세 경로는 모두 하나의 `docsLlms`에서 나옵니다. 페이지 트리(`source`)를 `fumadocs-core`의 `llms()`에 넘기고, 각 페이지는 제목과 주소 아래에 처리를 마친 본문을 붙여 그립니다(`apps/docs/src/shared/lib/source.ts`). 처리된 본문을 보관하려면 `defineDocs`에서 `postprocess: { includeProcessedMarkdown: true }`를 켜야 합니다.

문서의 블록은 Markdown에서 에이전트가 쓸 수 있는 내용으로 풀어서 냅니다.

| 문서의 블록        | Markdown에서 나오는 것    |
| ------------------ | ------------------------- |
| `ComponentPreview` | 예시의 소스 코드          |
| `InstallTabs`      | 패키지 매니저별 설치 명령 |
| `PropsTable`       | props 표                  |
| `RepoFile`         | 저장소 소스 파일의 내용   |

실제로 그려진 모습(스크린샷, 색 견본)은 Markdown에 없습니다. 시각적인 확인이 필요하면 Storybook이나 사이트를 직접 보십시오.

### `llms.txt`

[`/llms.txt`](/llms.txt)는 페이지 트리 그대로 제목, 주소, 한 줄 설명을 나열합니다. 한 줄 설명은 이 색인에만 있고 페이지별 Markdown에는 없습니다. 에이전트는 먼저 이 파일로 필요한 페이지를 고른 뒤 그 페이지의 `.md`만 읽는 순서가 가장 가볍습니다.

### `llms-full.txt`

[`/llms-full.txt`](/llms-full.txt)는 모든 페이지의 본문을 하나로 이어 붙입니다. 크기가 커서(지금 약 380KB) 에이전트의 컨텍스트를 많이 차지합니다. 문서 전체가 정말 필요할 때만 쓰고, 보통은 색인과 페이지별 Markdown을 쓰십시오.

### `*.md`

모든 페이지 주소 뒤에 `.md`를 붙이면 그 페이지의 Markdown 본문이 나옵니다.

```bash
curl https://<문서-주소>/docs/components/badge.md
```

`next.config.mjs`의 `rewrites`가 `/docs/<경로>.md`를 내부 라우트(`/llms.mdx/docs/<경로>/content.md`)로 보냅니다.

#### `Accept`

주소 뒤에 `.md`를 붙이기 어려운 도구를 위해, 요청이 HTML보다 `text/markdown`을 먼저 요구하면 같은 `/docs/...` 주소에서 Markdown을 돌려줍니다.

```bash
curl -H "Accept: text/markdown" https://<문서-주소>/docs/components/badge
```

- `/docs` 아래 주소에만 적용됩니다. 브라우저의 일반 요청(`text/html`, `*/*`)은 그대로 HTML입니다.
- 응답에 `Vary: Accept`를 붙입니다. 앞단에 CDN 같은 공유 캐시를 두면 그쪽에서도 `Accept`로 캐시를 나누도록 설정해야 같은 주소의 HTML과 Markdown이 섞이지 않습니다.
- 구현은 앱 루트의 `proxy.ts`(Next의 파일 규약)와 `src/_app/markdown-negotiation.ts`입니다.

### 페이지 액션

각 문서 페이지 제목 아래에 두 가지가 있습니다.

- **Copy Markdown**: 그 페이지의 Markdown을 클립보드에 복사합니다. 에이전트 대화창에 그대로 붙여 넣을 수 있습니다.
- **Open**: 그 페이지의 Markdown 주소를 ChatGPT, Claude, Cursor 등으로 넘기거나, Markdown과 소스를 GitHub에서 엽니다.

## 에이전트에서 쓰는 순서

Claude Code에서 이 문서를 근거로 컴포넌트를 쓰게 하려면 이 순서를 권합니다.

1. `/llms.txt`로 필요한 페이지를 고릅니다.
2. 그 페이지의 `.md`를 읽습니다. 설치 명령, 예시 코드, props, 접근성 설명이 한 번에 들어 있습니다.
3. 컴포넌트는 `shadcn`으로 설치합니다. 이 저장소의 레지스트리는 Radix 기반 프로젝트(`shadcn init -b radix`)에서만 올바르게 설치됩니다. 자세한 내용은 [소개](/docs)를 보십시오.

## 알아 둘 점

- 이 사이트가 호스팅되기 전에는 위 예시의 `<문서-주소>`를 개발 서버 주소(`http://localhost:3001`)로 바꿔 쓰십시오.
- MCP 서버처럼 에이전트가 문서를 직접 질의하는 경로는 아직 없습니다.
