## 결정

차량 3D는 **Three.js와 React Three Fiber**를 그대로 씁니다. Babylon.js로 바꾸지 않습니다.

## 왜 비교했나

프론트엔드 채용에서 3D 경험이 어느 라이브러리 기준으로 평가되는지가 궁금했습니다. Babylon.js를 요구하는 공고가 더 많다는 이야기가 있어서 생태계 지표를 직접 재 봤습니다.

## 측정 (2026-10-12)

| 지표                          | Three.js 쪽                     | Babylon.js 쪽                               |
| ----------------------------- | ------------------------------- | ------------------------------------------- |
| 핵심 패키지 월 다운로드 (npm) | `three` 83,509,977              | `@babylonjs/core` 1,738,019                 |
| React 바인딩 월 다운로드      | `@react-three/fiber` 25,514,308 | `react-babylonjs` 15,530, `reactylon` 1,118 |
| GitHub 별                     | `mrdoob/three.js` 116,289       | `BabylonJS/Babylon.js` 26,156               |
| 라이선스                      | MIT                             | Apache-2.0                                  |

핵심 패키지 기준으로 Three.js 쪽이 약 **48배** 큽니다. React 바인딩은 약 1,600배 차이가 납니다.

## 측정하지 못한 것

채용 공고의 실제 수와 요구 기술은 직접 세지 못했습니다. 그래서 "Babylon.js 공고가 더 많다"는 말을 확인하지도 반박하지도 못합니다. 이 결정은 생태계 규모와 이미 구현된 코드의 재사용성에 근거한 것입니다.

## 이유

1. **이미 구현한 것이 있습니다.** 도장 색(MeshPhysicalMaterial 클리어코트), HDR 조명, 그림자, 반쪽 메시 미러링, GSAP 스크롤 연동이 Three.js로 동작합니다. 엔진을 바꾸면 이 코드를 처음부터 다시 써야 합니다.
2. **React 생태계가 훨씬 큽니다.** 이 레포는 React 19 기반이고, 바인딩의 유지보수와 예제, 질문과 답변이 Three.js 쪽에 압도적으로 많습니다.
3. **Babylon.js의 장점은 이 프로젝트에 결정적이지 않습니다.** 내장 Inspector, TypeScript 우선 설계, 제품 구성기용 PBR 기능은 매력적이지만 이미 Three.js로 같은 결과를 냈습니다.

## 되돌릴 조건

3D 코드는 별도 패키지 `@repo/vehicle-3d`에 있습니다. `three`와 `@react-three/fiber`는 이 패키지의 의존성이고, 디자인 시스템(`@repo/ui`)과 앱은 작은 API(`viewer`, `vehicles`, `paints`, `constants`)만 씁니다. 이전에는 "three는 Storybook 전용, 앱에서 import 금지"였는데, 견적 앱이 3D를 쓰려면 이 규칙을 바꿔야 해서 **'three는 `@repo/vehicle-3d`에만'**으로 완화했습니다. 나중에 엔진을 바꿔야 하면 패키지 안쪽만 바꾸면 됩니다. 모델 파일(약 41MB)은 패키지에 싣지 않고 호스트(Storybook, 앱)가 `/models/`로 제공합니다.

## 라이선스 메모

BMW X5 G05 모델은 BMW Car IT의 CC BY 4.0 공개본입니다. 앱에 포함하면 제작자, 출처, 라이선스, 보증 부인, 수정 사실을 표기하고 BMW 상표가 허가된 것이 아님을 밝힙니다. 앱에는 웹용으로 줄인 부품(.glb, 6.5MB, 엠블럼 제외)과 CC0 HDR만 커밋하고 40MB 원본은 커밋하지 않습니다. 제3자 에셋의 조건은 루트 `NOTICE`에 모아 둡니다. 자세한 표기는 레포의 `.storybook/public/models/README.md`에 있습니다.
