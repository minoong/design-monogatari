## 결정

문서 사이트는 **Fumadocs**로 만들어요. Nextra는 같은 조건으로 측정해서 대안으로 남겨 뒀어요.

## 왜 비교했나

이 레포는 Next.js 16.4, React 19.3, **TypeScript 7.0.2**, Tailwind CSS v4 조합이에요. 문서 프레임워크가 이 조합에서 실제로 동작하는지는 문서만 읽어서는 알 수 없어서, 버리는 워크트리에 최소 구성을 올려 측정했어요.

## 후보

| 후보                    | 이 레포에서 확인한 것                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| **Nextra 4.6.1**        | 두 가지를 고정하면 동작해요. 고정 없이는 동작하지 않아요.                                 |
| **Fumadocs 16.17.1**    | 고정 없이 동작해요.                                                                       |
| 직접 구현 (`@next/mdx`) | 가능하지만 사이드바, 목차, 검색, 코드 하이라이트를 모두 만들어야 해요.                    |
| Docusaurus, Starlight   | Next.js가 아닌 별도 도구 체인이라 레지스트리를 같은 앱에서 호스팅하는 구조와 맞지 않아요. |

### Nextra를 쓰려면 필요한 두 고정

1. **`zod`를 4.3.x 이하로 고정**: Nextra가 허용하는 범위(`^4.1.12`) 안에서 zod 4.4.0부터 `Layout`의 스키마 검증이 `Invalid input: expected nonoptional ... at children`으로 실패해요. 모노레포 밖 빈 폴더에서도 똑같이 재현돼서 Turborepo 탓이 아니에요. 4.3.6까지는 정상이고 4.4.0, 4.4.1, 4.4.3, 4.5.4, 4.6.x는 실패했어요.
2. **docs 앱에만 `typescript@5.9.3`**: 코드 하이라이트용 `twoslash`가 모듈을 불러올 때 무조건 초기화되는데, TypeScript 7에는 `ts.sys`가 없어 빌드가 실패해요. Nextra의 옵션으로는 끌 수 없었어요.

## Fumadocs 스파이크 결과

TypeScript 7.0.2에서 **zod와 TypeScript 고정 없이** 측정했어요. 필수 게이트는 모두 통과했어요.

| 게이트                                        | 결과           | 측정 내용                                                                                                                                                       |
| --------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 설치, dev, 빌드, 타입 체크, `turbo run build` | 통과           | 고정 없이 모두 통과                                                                                                                                             |
| `.source` 생성물과 CI                         | 통과           | `fumadocs-mdx@15.4.7`에 postinstall이 없어 `allowBuilds` 변경이 필요 없고, `check-types`도 스크립트 변경이 필요 없어요                                          |
| MDX 안에서 `@repo/ui` 렌더                    | 통과           | `Button`의 hover, 누름(`whileTap` 0.96), 포커스 링과 `Dialog`의 열기, Esc, 포커스 복귀를 브라우저에서 확인                                                      |
| 토큰 공존 (라이트/다크)                       | 통과, 수정 1건 | 테마 전환이 `html.light`/`html.dark`로 정상이고 Button이 우리 토큰 값 그대로예요. 전역 CSS의 `a { color: inherit }` 리셋이 Fumadocs 링크 색을 덮어써서 지웠어요 |
| `AutoTypeTable`로 Button props                | 통과           | `variant`, `size`, `display`, `radius`, `icon`, `loading`, `asChild`를 값과 함께 출력해요 (Storybook은 못 하던 부분)                                            |
| 한국어 검색                                   | 부분 통과      | "버튼"은 4건, "다이얼로그"는 2건이에요. 조사가 붙은 "버튼은"은 0건이에요                                                                                        |
| ESLint                                        | 통과           | `.source`는 점 폴더라 별도 ignore가 필요 없어요                                                                                                                 |
| 스크롤 시 사이드바 고정                       | 통과, 수정 1건 | `html, body { overflow-x: hidden }`은 body를 스크롤 컨테이너로 만들어 sticky를 깨뜨려요. `clip`으로 바꾸면 1200, 1440, 640px에서 모두 정상이에요                |

## 고른 이유

1. **TypeScript 7과 함께 동작해요.** `fumadocs-typescript`가 `typescript ~7.0.2`에 의존해서 이 레포의 컴파일러와 같은 버전을 겨냥해요. Nextra는 영구적인 우회 두 개가 필요해요.
2. **shadcn 문서 페이지에 가까운 부품을 갖고 있어요.** 탭, 패키지 매니저 전환, 코드 복사, 우측 목차, 이전/다음, 검색을 기본으로 제공해요.
3. **필요하면 UI를 우리 컴포넌트로 바꿀 수 있어요.** `fumadocs-core`는 UI 없이도 쓸 수 있고, `npx @fumadocs/cli customize`로 레이아웃을 레포 안 소스로 가져올 수 있어요.
4. **에이전트를 위한 기능이 있어요.** `llms.txt`, 페이지별 Markdown, 문서를 MCP 도구로 노출하는 기능이 있어요. 이 레포의 AI 워크플로우 주제와 맞아요.

참고로 npm 주간 다운로드는 `fumadocs-core` 약 199만, `nextra` 약 24만이었어요 (2026-10 측정). 인기가 품질을 보장하지는 않아서 이 결정의 근거로는 쓰지 않았어요.

## 감수한 것

- **Base UI 판을 써요.** 공식 사이트의 둥근 패널 레이아웃(Spacious)은 Radix 판 `fumadocs-ui`에는 없고 Base UI 판 `@fumadocs/base-ui`에만 있어요. 처음에는 기본 `docs` 레이아웃을 택했다가 공식 사이트와 너무 달라서 `@fumadocs/base-ui`로 옮겼어요. 디자인 시스템(`@repo/ui`)은 계속 Radix예요. 문서 크롬만 Base UI이고, 문서에 보여 주는 컴포넌트와는 섞이지 않아요.
- **색은 공식 사이트와 달라요.** 레이아웃 구조는 같지만 팔레트는 우리 토큰(Apple 계열 파랑, 흰색과 검정 배경)이라 공식 사이트의 호박색 강조와 회색 패널 배경과는 달라요.
- **한국어 검색은 접두 일치 수준이에요.** 조사가 붙은 어절은 찾지 못해요.
- **새 의존성이 늘어요.** `fumadocs-core`, `@fumadocs/base-ui`, `fumadocs-mdx`, `@types/mdx`예요.
- **`@repo/ui`의 라디우스 토큰(11px, 18px)이 문서 크롬까지 키워요.** 크롬 요소에만 Fumadocs 기본값으로 되돌렸어요.

## 되돌릴 조건

필수 항목이 깨지면 Nextra로 옮겨요. 내용은 MDX와 프레임워크에 독립적인 문서 블록(미리보기, 설치 탭, props 표)에 두어서 테마만 바꾸면 되도록 설계해요.
