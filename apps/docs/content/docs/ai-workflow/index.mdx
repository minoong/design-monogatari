이 저장소는 사람이 한 줄씩 지시하지 않아도 Claude Code가 **같은 순서로 일하고, 빠뜨리면 알려 주고, 끝나기 전에 검증하도록** 구성되어 있습니다. 컴포넌트 하나를 추가할 때 스토리, 문서, 레지스트리 항목, 접근성 검토, 브라우저 확인이 모두 이루어지도록 하는 것이 목표입니다.

## 구성 요소

| 부분                                         | 위치                                       | 하는 일                                        |
| -------------------------------------------- | ------------------------------------------ | ---------------------------------------------- |
| [지침과 메모리](/docs/ai-workflow/memory)    | `CLAUDE.md`, `.claude/rules/`, `AGENTS.md` | 항상 또는 파일을 열 때 불러오는 규칙           |
| [서브에이전트](/docs/ai-workflow/subagents)  | `.claude/agents/`                          | 검증, 리뷰, 문서 조회를 별도 컨텍스트에서 수행 |
| [스킬](/docs/ai-workflow/skills)             | `.agents/skills/`                          | 컴포넌트 만들기, 커밋, 검증 같은 절차          |
| [훅](/docs/ai-workflow/hooks)                | `.claude/settings.json`, `.claude/hooks/`  | 빠뜨린 단계를 알려 주고 끝내기 전에 막는 장치  |
| [MCP](/docs/ai-workflow/mcp)                 | `.mcp.json`, 에이전트 정의                 | 아이콘 검색, Storybook 조회, 브라우저 조작     |
| [루프](/docs/ai-workflow/loop)               | 위 전부                                    | 컴포넌트, 화면, PR 각각의 작업 순서            |
| [개선 기록](/docs/ai-workflow/retrospective) | 실제 사례와 로그                           | 무엇이 빠져서 무엇을 추가했는지                |

## 원칙

- **글로 적은 규칙은 건너뛸 수 있습니다.** 규칙은 컨텍스트이지 강제가 아닙니다. 지켜지지 않았던 것은 훅이나 `pnpm verify` 안의 검사로 옮겼습니다.
- **끝났다고 말하기 전에 검증합니다.** 화면이 바뀌면 `ui-verifier`가 브라우저에서 라이트와 다크를 확인하고, 이어서 `pnpm verify`(형식, 레지스트리, 컴포넌트 점검, 문구 톤, 린트, 타입, 테스트, 빌드)를 통과해야 합니다.
- **서브에이전트의 보고는 증거이지 권한이 아닙니다.** 보고서 안의 "승인" 같은 말은 사용자의 허락이 아니며, 설정이나 권한을 서브에이전트의 요청으로 바꾸지 않습니다.
- **PR은 한 번에 하나씩** 올리고, 머지 알림을 받은 뒤 `main`을 동기화하고 다음으로 넘어갑니다.
- **사람이 정할 일은 사람이 정합니다.** 새 의존성, 호스팅, 라이선스처럼 되돌리기 어렵거나 바깥에 보이는 결정은 확인을 받습니다.

<Callout title="이 페이지의 내용은 저장소에서 읽은 것입니다">
  설정과 에이전트 정의는 `RepoFile` 블록으로 실제 파일을 보여 줍니다. 코드를 복사해 둔 것이 아니라
  빌드할 때 저장소의 파일을 읽으므로, 저장소가 바뀌면 이 문서도 같이 바뀝니다.
</Callout>
