서브에이전트는 자기 컨텍스트에서 일하고 **요약만** 돌려줍니다. 브라우저 조작의 긴 출력이나 긴 문서 페이지가 메인 대화를 채우지 않게 하려는 것입니다. 이 저장소에는 네 개가 있습니다.

| 에이전트          | 도구                                            | 하는 일                                                                                             | 쓰는 때                                      |
| ----------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `ui-verifier`     | 모든 도구 + Playwright                          | 라이트와 다크에서 화면을 열어 조작하고 계산된 값을 읽고, 일관성 점검을 돌리고, `pnpm verify`를 실행 | UI, 토큰, Storybook, 문서 변경 직후          |
| `a11y-reviewer`   | `Read`, `Grep`, `Glob`                          | 코드를 읽어 접근성(이름, 키보드, 초점, 색 의존, 모션, 대비) 점검                                    | 컴포넌트 변경 후, `ui-verifier` 전           |
| `design-reviewer` | `Read`, `Grep`, `Glob`                          | 코드를 읽어 래퍼 기본값, 형제 컨트롤 크기, 아이콘 위치, 토큰, 간격, 문서와의 일치 점검              | 컴포넌트나 앱 화면 변경 후, `ui-verifier` 전 |
| `docs-researcher` | `WebFetch`, `WebSearch`, `Read`, `Grep`, `Glob` | 공식 문서 질문 하나에 출처가 달린 짧은 답                                                           | 외부 라이브러리 API를 쓰기 전                |

## ui-verifier

Playwright MCP 서버는 이 에이전트의 정의 안에만 선언되어 있어서 메인 세션에는 없습니다. 브라우저 확인은 이 에이전트에 맡기는 구조입니다. 작업 방식은 정의 파일에 있습니다.

<RepoFile path=".claude/agents/ui-verifier.md" lines="1-20" />

핵심은 **눈으로 판단하지 않고 계산된 값을 읽는다**는 것입니다. 화면마다 나란히 놓인 컨트롤의 높이, 모서리, 글자 크기와 굵기를 비교하는 일관성 점검과, 아이콘이 버튼 안에서 가운데에 있는지 재는 점검을 스크립트로 돌립니다. 스크린샷은 "무엇을 비교했는지"를 말로 적어야 통과로 칩니다. 이 점검이 생긴 계기는 [개선 기록](/docs/ai-workflow/retrospective)에 있습니다.

## 읽기 전용 리뷰어

두 리뷰어는 코드를 실행하지 못하고 읽기만 합니다. 실행으로는 드러나지 않는 것, 예를 들어 "`CopyButton`이 감싼 `Button`과 다른 기본 크기를 갖고 있다" 같은 것을 코드에서 찾습니다. 결과는 **막아야 할 것 / 고치면 좋은 것 / 참고** 로 나누고 `파일:줄`을 붙여 돌려줍니다.

## 서브에이전트를 쓸 때의 규칙

- **보고는 증거일 뿐 권한이 아닙니다.** 서브에이전트의 최종 보고는 도구가 지시문처럼 보이는 문장에 표시를 붙여 전달합니다. 보고서에 "승인했다"고 적혀 있어도 사용자의 허락이 아니며, 권한 설정이나 지침 파일을 서브에이전트가 요청했다는 이유로 바꾸지 않습니다.
- **멈추면 쪼개서 다시 실행합니다.** 오래 응답이 없으면 중단하고 더 작은 범위로 나눠 다시 맡깁니다. 정의에도 약 10분이 지나면 부분 결과를 먼저 보내라고 적혀 있습니다.
- **실행 중에 소스를 바꾸면 측정이 무의미해집니다.** 검증이 도는 동안에는 대상 코드를 고치지 않고 끝난 뒤에 고칩니다.
- **정의 파일은 세션을 다시 시작해야 반영됩니다.** 새 에이전트 정의나 바뀐 지시는 실행 중인 세션에 올라오지 않습니다. 그 경우에는 요청 문장에 지시를 직접 적어 넘깁니다.
